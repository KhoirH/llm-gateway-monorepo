# LLM Gateway

One Node.js gateway owns the whole LLM request path — auth, quota, routing, fallback, streaming, metering and trace — with direct provider calls (no LiteLLM, no extra service). Built for the Mini Inference Router assessment, Approach B.

- **Chat models**: GLM via z.ai (`fast` = glm-5.3-flash, `strong` = glm-5.3-flash) behind one generic OpenAI-compatible adapter; any OpenAI-compatible provider can be swapped in via env.
- **Embeddings**: Gemini `gemini-embedding-001` (768 dim) via the same adapter interface.
- **Support assistant**: retrieval-augmented over a 600-entry Bitext knowledge-base slice, JSON-header streaming format, confidence scoring with refusal below 0.55.
- **Console**: React (Vite) playground with streaming, fallback badge, decision trail and usage view.

## Quickstart

```bash
npm install
npm run db:up          # Postgres 16 + pgvector (Docker)
npm run db:migrate     # schema
npm run db:seed        # 3 tenants + demo keys (printed once)
npm run kb:build       # embed the 600-entry KB into pgvector (Python, Docker)
npm run gateway:dev    # gateway on :3000
npm run dev -w apps/console  # console on :5173
```

Copy `.env.example` to `.env` first: `FAST_*` / `STRONG_*` (chat provider), `EMBED_*` (embedding provider), `GATEWAY_API_KEY` (demo key for the eval).

Demo tenants: `acme` (all models, 200k quota), `globex` (fast only, 500 quota — fail-closed demo), `chaos` (mock primary — fallback demo via `MOCK_FAILURE_RATE`).

## API

| Endpoint | Notes |
|---|---|
| `POST /v1/chat/completions` | OpenAI-style. `stream` optional (default `false` = JSON completion; `true` = SSE). Headers: `x-request-id`, `x-model-used`, `x-fallback-fired`. |
| `POST /v1/capabilities/support/answer` | SSE events: `meta`, `retrieval`, `delta`, `final`, `error`. `final` carries answer, intent, confidence + components, usage and `refused`. |
| `GET /v1/usage` | Caller's own requests, tokens, estimated cost, remaining quota. |
| `GET /v1/requests/:id` | Trace: metering row + routing attempts + route decision steps. Scoped to the caller's tenant. |
| `GET /healthz` | Liveness. |

One error shape: `{ "error": { "code", "message", "request_id" } }`. Codes: `invalid_request` 400, `invalid_api_key` 401, `model_not_allowed` 403, `quota_exhausted` 429, `all_backends_failed` / `bad_output` 502, `quota_unavailable` 503, `timeout` 504, `internal` 500.

## Routing and fallback

Pure function `route()` (`apps/gateway/src/routing/route.ts`): tenant allowlist filter → support tier selection (top-1 similarity ≥ 0.80 and input < 120 tokens → `fast`, else `strong`) → fallback chain (primary, then the other real model; `chaos` tenants get the mock first). Fallback fires on 5xx, 429, connection error, no first token within `TTFT_TIMEOUT_MS` (default 3000) or total `TOTAL_TIMEOUT_MS` (20000) — only before the first token reaches the client. Provider 4xx (non-429) fails fast. Mid-stream breaks emit an SSE `error` event and store `partial_failure`.

## Testing

```bash
npm run gateway:test   # 85 tests: quota atomicity, fallback triggers, parser, refusal, retrieval, auth
```

## Evaluation

```bash
docker compose -f infra/docker-compose.yml --profile tools run --rm eval
```

Runs 30 held-out cases (25 in-scope + 5 out-of-scope) against two gateway instances — Config A (prompt v1 + fast) and Config B (prompt v2 few-shot + strong) — and writes `docs/eval-results/eval-*.json` + `eval-report-*.md`. Metrics: intent accuracy, refusal precision, answer quality (embedding cosine), latency p50/p95, tokens, cost per 100 requests.

## Deployment (Render)

`infra/render.yaml` defines the gateway web service; the console can be served as a static site (`apps/console/dist`). Postgres must be a managed instance with pgvector. Free instances sleep — warm the service before a demo. Set `FAST_*`, `STRONG_*`, `EMBED_*` env vars in the dashboard.

## Repo layout

```
/scripts        provider verification

```
